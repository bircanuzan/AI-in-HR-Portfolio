# Thousands-of-engineers rollout playbook — illustrative, not executed

## Pilot-to-scale plan
- **Weeks 1-2: readiness.** Source inventory, priority teams, approval gates, engineering owners, privacy/security evaluation, supported repository patterns and baseline time sampling.
- **Weeks 3-4: bounded pilot.** 50-100 consenting engineers, preapproved tasks, agent demonstrations, review evidence, transparent support and risk triage.
- **Weeks 5-8: expansion.** Release to 250-500 engineers if pilot quality gates pass. Train team champions, record qualitative feedback and review telemetry.
- **Weeks 9-12: progressive rollout.** Add cohorts subject to IT operations capacity, quality, support load and access approvals. Growth to thousands is an **illustrative target**, not a deployment claim.
- **Ongoing: continuous improvement.** Track weekly activation and approved task outcomes, incident lessons, engineering satisfaction and finance-aligned value.

## Enablement curriculum
1. What the coding agent can and cannot do; acceptable tasks
2. Repository onboarding, protected branches and permissions
3. Break down a task into testable acceptance criteria
4. Validate agent-produced tests, changes and explanations
5. Handle failures, rollback and human escalation
6. Measure actual value: task time and quality evidence, not outputs counted as "completed" by a model
7. Champion toolkit for team leads and peer learning

## Quality/rollout gates
No unauthorized data exfiltration or unreviewed deployment. All changes require agreed code-review rules. Escaped defects, failed builds, vulnerability findings and rework must not worsen beyond sponsor-approved thresholds. Permission revocation and incident reporting are tested.

## Weekly cadence
Account team Monday value review; engineering leads Tuesday workflow quality; CoE Wednesday office hours; security and incident review Thursday; sponsor executive summary Friday. Actual cadence must reflect customer preference and timezone availability.

## Support model
Level 1 user enablement; Level 2 platform/repo integration; Level 3 security/product escalation. Written SLAs to be agreed. No unsupported claim of product vendor SLA.
