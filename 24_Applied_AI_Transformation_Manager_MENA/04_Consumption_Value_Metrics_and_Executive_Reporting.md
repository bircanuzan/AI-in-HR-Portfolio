# Consumption, adoption and value realization — MENA strategy dashboard

## Synthetic model, NOT customer data
Run src/value_capture.py on fictional accounts data to calculate **account-level adoption, potential effort released, discounted capacity value and usage cost assumptions**. The model is NOT proof that a coding agent generated quality improvements, ROI, cash savings or engineer performance.

## Metric dictionary
| Metric | Definition | Why it matters |
|---|---|---|
| Activated engineers | Distinct engineers who have started allowed agent workflows / eligible engineers | True rollout coverage |
| Consuming engineers | Engineers with verified usage in selected period | Ongoing adoption |
| Agent-involved tasks | Eligible tasks with traceable agent assistance | Consumption quality |
| Approved completions | Human-reviewed accepted outcomes | Quality, not simply usage |
| Baseline vs assisted minutes | Matched eligible task sample with consistent method | Conservative productivity estimation |
| Rework, defects, vulnerabilities | Revisions and incidents by task severity | Risk-adjusted quality |
| Capacity value hypothesis | Supported time delta × validated conversion assumptions | Potential, not booked ROI |
| Realized financial impact | Finance-certified avoided spending / income contribution net of all incremental costs | Only realized when evidenced |

## Hypothetical account KPIs
Report account, eligible engineers, activated engineers, activation rate, quality factor, estimated weekly tasks, modeled hours released/month, usage cost, and hypothetical capacity value. Use deployment stage and cohort filters. Include denominator and method annotations in every sponsor deck.

## Executive readout
1. Decisions requested: scope, quality gate and next cohort.
2. Rollout by account, region and cohort.
3. Quality and safety defects with accountable owners.
4. Usage and context: workloads, accepted outcomes and no-go tasks.
5. Financial *hypothesis* with transparent assumptions, sensitivity and finance signoff status.
6. Risks, customer trust, account growth conditions and upcoming programme milestones.

## Value caveats
Do not equate an activated seat with productive use, faster completion with higher code quality, working time released with labor cost savings, consumption with realized ROI or time saved with headcount reduction. Measure displacement, rework, long-term maintainability and operational incident costs.

## Governance
Account sponsor and Cognition account team jointly review delivery status. CoE owns standard operating playbook. Finance owns monetary claims. Engineering leadership owns code/reliability measures. Security approves tool access and incident controls.
