# 01 | Interactive eLearning — Service Request Triage

**Delivery:** [Open interactive HTML module](lesson.html) (download and open in any modern browser). Working demonstration of a self-contained digital learning unit; not Storyline or Rise 360.

**Audience:** corporate facilities service coordinators / supervisors. **Duration:** 8–10 minutes.

**Business problem:** Learners may log facilities service requests with insufficient information, fail to distinguish safety-critical issues from routine maintenance, or omit handoff confirmation.

**Objectives (Bloom):** (1) classify safety-critical vs routine requests; (2) select the correct owner and response route in a scenario; (3) produce an auditable handoff note with essential facts.

**Flow:** introduction → model process → branching decision point → multi-item knowledge check → score/feedback.

**Design decisions:** realistic field language; no reliance on proprietary EFS data; hypothetical rules shown inside each screen; required user interaction; formative feedback explains *why*; end-of-module feedback.

**Assessment:** three decision questions; 2/3 satisfactory demonstration threshold. No learner personal information is collected.

**Technology:** self-contained HTML/CSS/vanilla JavaScript; responsive; keyboard-accessible buttons; screen reader labels, progress indicator, optional SCORM 1.2 LMS API calls. **SCORM interface is unverified until tested in a real LMS.**

**Authoring disclosure:** created as an AI-assisted portfolio demonstration for candidate review, not a past client deliverable; no claim of hands-on Storyline or Rise 360 use.

**Suggested next validation:** conduct SME review against approved operating procedures, test keyboard and mobile use, package/test on SCORM Cloud or an LMS, verify accessibility and tracking.
